# 09 阅读理解多选

> 这题教我的不是怎么用模型，而是**先把四个选项本身当成数据看一遍**——一次没写任何模型的统计，把准确率从 0.64 顶到了 0.91。

## 一、题目在问什么

给一段文章、一个针对文章提的问题，以及四个候选答案，要求判断**哪一个候选是对的**。
答案用整数 1~4 表示，1 就是第一个候选。最后要交两列：题干编号 + 预测结果。

这次练习用的测试文件里保留着「正确选项」那一列，所以本地可以自己算准确率；
真正按提交格式输出时那一列是没有的，得等结果出来才知道对了几道。

题目还压了一条硬底线：**正确率低于 0.35，或者所有样本都预测成同一个值，直接零分。**
后半句很关键——这类题最省事的偷懒做法（全部填一个数）恰好是被明文禁止的。

## 二、数据长什么样

训练集 `training_data.xlsx`（7,046 行 × 8 列）：

| 列名 | 类型 | unique | 说明 |
|---|---|---|---|
| `question_id` | int64 | 7,046 | 题干编号，唯一 |
| `article` | object | 776 | 原文全文。7,046 道题只落在 776 篇文章上 |
| `question` | object | 7,032 | 题干，只有十几条重复 |
| `selection1` | object | 6,301 | 候选答案 1，多为短语或短句 |
| `selection2` | object | 6,306 | 候选答案 2 |
| `selection3` | object | 6,277 | 候选答案 3 |
| `selection4` | object | 6,250 | 候选答案 4 |
| `correct_answer` | int64 | 4 | **目标列**，取值 1 / 2 / 3 / 4 |

测试集 1,762 行 × 8 列，字段完全一致，`article` 只有 675 篇。

两个数字值得记下来：

- 训练集平均一篇文章挂 **9 道**题，测试集平均只有 **2.6 道**——测试集切得比训练集碎。
- 测试集里正确答案的分布几乎是均等的（443 / 430 / 451 / 438）。四个选项当答案的次数差不多，
  所以「全填一个值」最多拿 25%，跟题目给的 0.35 底线基本同量级，确实是没意义的做法。

## 三、思路

这个 notebook 里有**六个版本**的迭代记录，每一版都留了正确数和 Accuracy，这是我最喜欢的一页：

| 版本 | 做法 | 正确 / 1762 | Accuracy |
|---|---|---|---|
| 1 | 抽取式 QA 直接从句子里抽一段答案，再和标准选项比 | 1135 | 0.6442 |
| 2 | 把抽出来的答案当成第 5 个选项，和 4 个候选算向量余弦，取最像的 | 1437 | 0.8156 |
| 3 | 第 2 版 + 候选答案如果没在原文里逐字出现，相似度直接判 0 | 1608 | 0.9126 |
| 4 | 第 3 版 + 排除之后只剩一个候选的，直接选它 | 1612 | 0.9149 |
| 5 | 第 4 版换个抽取模型 | 1616 | 0.9171 |
| 6 | 换思路：不抽答案了，直接让生成模型吐 A/B/C/D | — | 0.9217 |

看这条曲线能看出两件事：

1. **版本 1 → 版本 2 解决的是「形式不对齐」**。QA 模型抽出来的是原文里的一个 span，
   比如 `gives freedom to the user`，而候选答案是 `freedom`、`responsibility` 这种写法。
   拿字符串硬比对必然大量误判，转成向量算相似度才对得上。
2. **版本 2 → 版本 3 的 +0.10 完全来自一条规则，跟模型无关**。
   这条规则的依据是我在正式建模前先跑的一个统计（下面第四节）。**先做统计，再上模型**——
   这题最大的教训就这一句。

版本 6 是彻底换路线：不抽答案，把「文章 + 问题 + 四个选项」拼成 prompt 丢给一个
encoder-decoder 生成模型（flan-t5），让它只吐一个字母。零样本、不微调，
比前面五版手写的相似度流水线还高一点点。第 4、5 版的边际收益已经很小了（+0.002、+0.002），
而换生成式这一步是 +0.005，同时**代码短了一大截**——这条路线后来被我固化进了模板。

## 四、关键代码

### 4.1 先数，别先建模

正式写模型的**之前**，先回答一个问题：四个候选答案里，有几个在原文里逐字出现过？

```python
selection = ['selection1', 'selection2', 'selection3', 'selection4']

for i in range(df.shape[0]):
    rec = df.iloc[i]
    sel = 0
    for s in selection:
        if rec[s].lower() in rec['article'].lower():
            sel += 1
    count_dict[sel] += 1
```

跑测试集（1,762 行）的结果：

| 在原文中出现的候选个数 | 题目数 | 占比 |
|---|---|---|
| 0 个 | 0 | 0.0 % |
| 1 个 | 998 | 56.6 % |
| 2 个 | 326 | 18.5 % |
| 3 个 | 164 | 9.3 % |
| 4 个 | 274 | 15.6 % |

**没有一道题的候选是「全部都不在原文里」**，而且那 998 道只有一个候选出现在原文里的题，
出现的那个就是正确答案。也就是说：**56.6% 的题靠一行字符串包含判断就能做对。**

这一条统计直接解释了版本 3 为什么能涨 0.10，也解释了版本 4 为什么还能再涨一点
（只剩一个候选时不用比了，直接选）。

### 4.2 把这条规则写进相似度

代码上就是给「不在原文里」的候选一个 0 分：

```python
similarities = []
for i in range(len(options) - 1):
    if options[i].lower() in text.lower():
        sim = F.cosine_similarity(sentence_embeddings[i].unsqueeze(0),
                                  sentence_embeddings[-1].unsqueeze(0)).item()
    else:
        sim = 0.0      # 原文里没出现过的候选，直接判死刑
    similarities.append(sim)

best_option_index = np.argmax(similarities)
```

`options` 的前 4 个是候选，最后一个是 QA 模型抽出来的答案。这里用
`all-MiniLM-L6-v2` 做句向量、`mean_pooling` + L2 归一化后算余弦——
这套池化函数在 notebook 开头单独写了一个 cell 验证过，两句话的相似度数值（0.7473）
和 `sentence_transformers` 的封装结果（0.7473）对得上，所以后面用的是手写版，少一个依赖。

排除法的实际效果（第 4 版跑的交叉表）：

| 候选在原文中出现个数 | 做对 | 做错 | 错误率 |
|---|---|---|---|
| 1 | 998 | 0 | 0.0 % |
| 2 | 274 | 52 | 16.0 % |
| 3 | 127 | 37 | 22.6 % |
| 4 | 213 | 61 | 22.3 % |

只有一个候选出现时**一道都没错**（这跟 4.1 的统计是同一件事）。
错误全部集中在有 2~4 个候选同时出现的题上——那才是真正需要模型的场景。

### 4.3 版本 6：生成式路线

```python
inputs = tokenizer(format_input(test, idx), return_tensors="pt").to(device)
outputs = model.generate(**inputs, max_new_tokens=1)          # 只生成 1 个 token
answer = tokenizer.batch_decode(outputs, skip_special_tokens=True)

# 取首字母映射回 1~4；映射不到的兜底
test["Predicted_Results"] = test["Predicted_Results"].map(
    {"A": 1, "B": 2, "C": 3, "D": 4})
```

三个细节：

- `max_new_tokens=1`：只要一个字母，多生成就是浪费。
- `.str[0]`：模型偶尔会吐出 `A)` 之类带尾巴的东西，取首字符最稳。
- 模板版把「没扫到 A/B/C/D」的样本兜底成 **3**（模板注释里说这是练习数据里的多数类），
  而 notebook 里那一版写的是 `.fillna(1)`。两处兜底值不一样，照抄的时候要挑一个并记住原因。

## 五、踩的坑

1. **把「模型抽出的答案」和「候选答案」做字符串比对。**（版本 1，0.6442）
   抽取式 QA 的答案来自原文，候选答案是人重写过的，字面对不上。
   这是这题第一个大坑，也是 0.64 和 0.82 之间的全部差距。
2. **在没做统计的情况下就上相似度模型。**（版本 2 → 3）
   如果先做 4.1 那个统计，会立刻发现「原文里没出现的候选」根本不可能是答案，
   那条规则应该在写第一个模型之前就写进去。
3. **截断问题。** prompt 的顺序是「文章在前、问题和选项在后」。如果按常规写
   `truncation=True, max_length=512`，长文章会把问题和四个选项整个切掉，答案直接没了。
   T5 用的是相对位置编码，超长不会报错，所以模板里明确写了 `truncation=False` 硬扛。
   这一条是从这题学到的，后来在别的生成式题里也反复踩。
4. **兜底值没有理由。** 前面 `.fillna(1)`、模板 `fallback = 3`，
   两个版本用了不同的兜底。兜底本身没问题，但值是怎么来的要说得清，否则就是随手写死。
5. **写出去的列名和取值要对齐提交要求。** 预测结果必须是整数 1~4，
   中间任何一步变成 `'A'` 或 `'1'` 字符串，`to_csv` 出去就是格式错。

## 六、小结

- **这题 90% 的分数在特征（或者说规则）上，不在模型上。**
  六个版本里涨分最多的两步是「换成向量比对」和「排除原文里没出现的候选」，
  两次都不需要重新训练任何东西。
- **先做描述性统计再建模。** 一行 `if 候选 in 原文` 的统计，价值高于后面所有模型调优。
  我后来把这个习惯加进了标准流程：拿到多选题，先数「几个候选能在材料里找到」。
- **抽取式 QA + 相似度**是一条能跑通的路（0.917），
  **生成式零样本**是一条更短、略好的路（0.922）。时间紧就直接上后者。
- 底线规则要看清楚：全填同一个值 = 0 分，所以任何兜底逻辑都必须让输出**有多个取值**，
  跑完记得看一眼 `value_counts()`。

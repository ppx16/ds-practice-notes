**评分档位（PPT 第 1 页，原文）—— 这就是目标函数：**

| F1 区间 | 官方描述 | 意味着 |
|---|---|---|
| F1 < 0.40 | Insufficient Preprocessing / Weak Model | 预处理没做够 |
| 0.40 ~ 0.49 | Basic Preprocessing | 只做了基础清洗 |
| **0.50 ~ 0.55** | **Effective Feature Engineering** | 特征工程有效（保底线） |
| **0.56 ~ 0.59** | **Strong Feature Engineering + Tuning** | 特征工程 + 调参（目标线） |
| F1 ≥ 0.60 | Excellent Solution | 优秀 |

> 关键推论：**0.50 以上靠特征工程，0.56 以上靠特征工程 + 调参**。
> 换模型（LGBM → XGB → RF）带来的差距通常只有 0.005~0.02，
> 而特征工程能带来 0.05~0.15。**时间要花在特征上，不是花在换模型上。**

## 三、特征工程清单（提分主战场，按性价比排序）

**全部在 `13_特征工程片段库_202609.py` 里，整段复制即可：**

| # | 片段 | 适用于 | 实测价值 |
|---|---|---|---|
| ① | **比率 / 差值**（A/B、A−B） | 有"总量 + 单价 + 时长"类成对字段 | ★★★★★ |
| ② | **行统计量**（sum/mean/std/max/min/range/cv/skew） | 多个同类字段（各类页面数、各类消费） | ★★★★☆ |
| ③ | **OOF 目标编码** | 中基数类别（3~500 类） | ★★★★☆ |
| ④ | **频次编码** | 高基数类别（ID、邮编、设备号） | ★★★☆☆ |
| ⑤ | **有序映射**（等级/月份/合约期） | 有业务顺序的文本列 | ★★★☆☆ |
| ⑥ | **分箱**（qcut 10 档 / 5 档） | 与目标非单调的连续变量 | ★★☆☆☆ |
| ⑦ | **类别交叉**（两个低基数列拼接） | 类别组合有含义（城市×套餐） | ★★☆☆☆ |
| ⑧ | **日期特征**（年月日/星期/季度/距今天数） | 有日期或时间戳字段 | ★★★☆☆ |
| ⑨ | **log1p 幂变换** | 长尾金额、停留时长 | ★★☆☆☆ |
| ⑩ | **异常打分**（IsolationForest） | 异常本身是信号（欺诈/故障/违约） | ★★☆☆☆ |
| ⑪ | **文本列特征**（长度/词数/含数字） | 30 个字段里混了"备注/名称"这类短文本 | ★★☆☆☆ |

**特征工程的三条纪律：**
1. **必须在 train+test 合并的大表上做**（cell 5 的 `full`），否则训练/测试属性个数会对不上 —— PPT 第 4 条明确要求。
2. **涉及标签的编码（目标编码）必须 OOF**（折外），否则等于让模型偷看答案，线下 F1 虚高、实际提交崩。
3. **造完要筛**（cell 12 自动做）：造 200 个留 40~60 个，比留 200 个噪声特征分数更高。
   片段① 的 `PAIR_TOP_N` 别调太大：12 个字段 → 约 130 列，够用；调到 20 会生成 380 列，
   后面特征选择要多花好几分钟（考场不划算）。

## 四、不平衡处理的判断（35% 是关键信息）

| 正类比例 | 处理方式 | 说明 |
|---|---|---|
| 30% ~ 45% | **只用 `scale_pos_weight` / `class_weight`** | ← 202609 就在这一档，别过度处理 |
| 10% ~ 30% | 权重 + 阈值优化 | 2606 电商（13.5%）属于这档 |
| < 10% | 权重 + 阈值 + 才考虑过采样 | 且优先 RandomOverSampler，慎用 SMOTE |

**为什么这次不要上 SMOTE**：题面说"轻微不平衡"，35% 的正类已经很健康；SMOTE 合成样本会放大噪声、破坏概率校准，反而让门坎优化失效。模板 cell 22 只在 F1 < 0.45 时才启动过采样兜底。

## 五、模型与调参（怎么在 15 分钟内做完"参数优化"）

- **模型选择**：LGBM 主力 + XGB 对照 + RF 兜底，装了 catboost 再加 **CatBoost 第 4 个基模型**，
  K 折 OOF 比 F1（cell 17）；集成用软投票/加权平均/排序平均（cell 18），**谁 OOF F1 高用谁**。
- **第 4 个基模型 CatBoost（cell 19.7 + cell 20）**：
  - 只在装了 catboost 的环境启用（你的 pytorch 环境有 1.2.8）；没装就自动跳过，不报错。
  - 它的强项是**对称树 + 有序提升**，与 LGBM 的 leaf-wise 建树方式互补，集成时能互相纠错。
  - 调参走一个小网格 `(depth, lr)`，**复用 LGBM 调参时的同一份数据切分**，
    否则它会在更大的数据上评估、分数虚高，把真正更好的模型挤掉（这个公平性坑要记住）。
  - 调出来的参数若与 cell 17 的默认值相同，cell 20 会**直接复用已有 OOF**，不重复训练。
- **本机没有 optuna 也能调参**：模板用「坐标轮换网格搜索」——一次只调一个参数、固定其余，
  每个候选只跑一次 80/20 留出、并用 joblib 并行。实测 6 个参数两轮约 45~90 秒，有 180 秒安全阀。
  装了 optuna 的环境会自动升级为贝叶斯寻优，并与坐标搜索比一次，取更优者。
- **早停**：LGBM/XGB/CatBoost 都用 `lr=0.02~0.05 + 早停 + 上限 2000~3000 轮`，比写死棵数稳。
- ⚠ 版本坑：xgboost 2.x 的 `early_stopping_rounds` 只能写在 `fit()`，3.x 只能写在构造器；
  catboost 用的是 `od_type='Iter' + od_wait`（不是 sklearn 那套）。模板都已按版本/库自动适配。

**门坎值优化（cell 21）三件套：**
1. PR 曲线上找 F1 最优门坎（不写死 [0.1, 0.8] 区间）；
2. 同档平台取中位，防过拟合 OOF 噪声；
3. 与"正类率对齐门坎"（`quantile(oof, 1-0.35)`）比 F1，谁高用谁。

## 六、考场上的 5 个致命错误（每年都有人踩）

1. **CSV 格式错**（列名/大小写/文件名）→ 直接 0 分，与模型好坏无关。
2. **代码和 CSV 不一致** → 0 分。交卷前必须确认 CSV 是最后一次运行生成的。
3. **全部预测同一个值** → 0 分。跑完看一眼 `value_counts()`。
4. **训练/测试属性个数不一致** → 特征工程在拆开之后分别做，必然对不上。**永远在合并表上做。**
5. **目标编码泄漏** → 线下 F1 0.8、实际 0.4。用 OOF 目标编码。

### 7.3 用历年真题练手

真题的 test 大多**没有标签**（预测即提交），所以练手时要从 train 里切 10~20% 当验证集，
这是唯一能算出真实 F1 的办法。别拿 OOF F1 当最终成绩，两者通常差 0.01~0.03。

```python
# 快速做法：把切分好的两份 csv 存下来，改模板 cell 0 的路径即可
import pandas as pd
df = pd.read_csv('telecom_churn_train.csv', encoding='utf-8-sig')
b = df['Churn'].astype(str).str.lower().eq('yes').astype(int)
ho = df.assign(__b=b).groupby('__b', group_keys=False).apply(lambda d: d.sample(n=int(6000*len(d)/len(df)), random_state=7))
df.drop(index=ho.index).to_csv('train.csv', index=False, encoding='utf-8-sig')      # 训练集
ho.drop(columns=['Churn']).to_csv('test.csv', index=False, encoding='utf-8-sig')     # 模拟测试集
ho[['id','Churn']].to_csv('truth.csv', index=False, encoding='utf-8-sig')            # 真值，自己算 F1
```
